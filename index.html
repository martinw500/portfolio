Motor temperature over CAN

I proposed adding motor temperature sensing to UBC Solar's car with a PT1000 RTD, then wrote the firmware for it, from a breadboard prototype to the driver on the Motor Drive Interface board.

  1. PT1000 RTDPlatinum sensor on the motor
  2. wire
  3. MAX31865Turns resistance into a reading
  4. SPI
  5. STM32 on the MDIMy driver and fault debounce
  6. CAN
  7. 0x502, once a secondSuccess, °C, fault flags
  8. telemetry
  9. GrafanaThe pit crew's dashboard

The tricky part was failures that look like data. If the MAX31865 is missing, SPI reads still succeed and return about −259 °C, which looks like a real temperature, so the driver checks the chip's config register before every conversion. A fault also has to persist for five reads before the flag is set, so one noisy reading doesn't raise an alarm.

Try unplugging the sensor in the table. It follows the same rules as the firmware. The last photo below is a real capture from the board with the sensor pulled.
